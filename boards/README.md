# 板子配置说明

一个板子 = 一份 JSON，只声明**数量分布**和**规则开关**，不声明任何行为。

行为（女巫能不能毒人、猎人被毒能否开枪）属于 `engine/roles.py` 和 D3 的结算函数，不属于这里。

> JSON 不支持注释，所以字段说明集中放在这个文件里。改板子前先读这里。

---

## 字段

### 顶层

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 板子唯一标识，必须与文件名一致（`9p.json` 的 id 就是 `9p`）。用于 URL、日志、评测集索引 |
| `name` | string | ✅ | 展示名，只给人看 |
| `roles` | object | ✅ | 身份 → 数量。key 必须是 `Roles` 的取值，见下 |
| `options` | object | 可省 | 规则开关，省略则用默认值（`sheriff: false`, 屠边） |

### `roles` 的 key

必须是 `engine/roles.py` 里 `Roles` 枚举的**值**，全小写：

```
wolf   villager   seer   witch   hunter   guard
```

- 写 `"Werewolf"`、`"werewolves"`、`"wolf "`（带空格）都会报错，不会静默忽略
- 数量必须 ≥ 1 且 ≤ 20，写 `0` 会报错
- 不需要的身份直接省略，不要写 0

### `options`

| 字段 | 类型 | 说明 |
|---|---|---|
| `sheriff` | bool | 是否开启警长竞选。`false` 时第一天直接进入夜晚→白天发言 |
| `win_condition` | string | `"slaughter_side"` = 屠边（神全死或民全死，狼胜）；`"slaughter_all"` = 屠城（好人全死才狼胜） |

### 为什么只有两个选项

判定标准：**这个开关在不同板子之间会取不同的值吗？** 会变的才放进来。

下面这些**不在这里**，因为它们全项目统一，属于 `engine/constants.py` 和各自的结算函数：

| 规则 | 归属 |
|---|---|
| 女巫首夜可自救，之后不能 | 常量 + D3 结算 |
| 猎人 / 狼王被毒不能发动技能 | D3 结算 + 单测 |
| 守卫不能连续两晚守同一人 | D3 结算 + 单测 |
| 平票 → PK → 再平票无人出局 | D4 投票逻辑 + 单测 |
| 退水是否允许 | 跟着 `sheriff` 走，不单独配置 |

不可配置的东西写成常量和单测，比写成配置项更安全：配置项可能被改错，单测会让改错变红。

## 现有板子

| id | 组成 | 人数 | 警长 | 用途 |
|---|---|---|---|---|
| `9p` | 3 狼 + 3 民 + 预女猎 | 9 | 否 | CI 回归、快速仿真、演示 |
| `12p` | 4 狼 + 4 民 + 预女猎守 | 12 | 是 | 主推板子，标准网杀 |

两个板子的狼人占比都是 33%，落在健康区间 25%–45% 内。

`9p` 没有守卫：守卫是 12 人板才有的第 4 个神职。身份只能从 `Roles` 里挑，不能凭空造。

## 加载器实现的校验

硬错误（抛 `BoardConfigError`，`problems` 里含全部问题）：

| # | 检查 | 由谁拦 |
|---|---|---|
| 1 | `id` 与文件名一致 | `load_board()` |
| 2 | `roles` 的 key 都在 `Roles` 里 | Pydantic（`dict[Roles, int]`） |
| 3 | 数量在 1–20 之间 | Pydantic（`Annotated[int, Field(ge=1, le=20)]`） |
| 4 | 没有多余字段 | Pydantic（`extra="forbid"`） |
| 5 | 总人数在 6–18 之间 | `_collect_problems()` |
| 6 | 至少 1 个狼人 | `_collect_problems()` |
| 7 | 唯一身份数量 ≤ 1 | `_collect_problems()`（读 `RoleSpec.unique`） |
| 8 | 技能依赖满足（有预言家/女巫就必须有狼） | `_collect_problems()`（读 `RoleSpec.requires`） |
| 9 | 屠边时神职和民各至少 1 个 | `_collect_problems()` |

软告警（`warnings.warn`，不拦）：

| 检查 | 区间 |
|---|---|
| 狼人占比 | 25%–45% |

### 两条最有价值的校验

第 8、9 条不自检"格式对不对"，而检"这个板子在逻辑上打不起来吗"：

- `seer` / `witch` 的 `requires` 里有 `wolf`。没有狼，验人和毒药都没有目标
- 屠边要求"神全灭"和"民全灭"两个分支都能成立，缺一边就是死规则

这两条靠 `RoleSpec` 里的数据驱动，**加新身份不用改校验器**——只改 `engine/roles.py` 的注册表。

## 加一个新身份时要改什么

以"骑士"为例，两处：

1. `engine/roles.py`：`Roles` 加成员 + `ROLE_REGISTRY` 加一条 `RoleSpec`（阵营、是否唯一、依赖谁）
2. 板子 JSON：在 `roles` 里写上数量

校验器、加载器、`faction_counts()` 都不用动。这是把"依赖关系做成数据"带来的好处。

---

## 报错长什么样

所有问题一次报全，不是遇到第一个就停：

```
boards/9p.json: 总人数 3 不在 6-18 之间; 板子里没有狼人; witch 依赖 wolf，但板子里没有（技能无目标）
```

改配置的人不该试 8 次才发现 8 个错。所以 `BoardConfigError.problems` 是列表，`__str__` 里用 `; ` 拼起来。
